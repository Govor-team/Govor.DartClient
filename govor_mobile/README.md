# Говор — Flutter-клиент

Экспериментальный порт MAUI-клиента на Dart/Flutter для Android, Windows, Linux и web. Основа контрактов — исходники Govor.Mobile и [документация API](https://nas-3.gitbook.io/govor-api). Клиент подключается к существующему ASP.NET Core серверу.

## Запуск

Используется Flutter 3.38.6 / Dart 3.10.7. Зависимости зафиксированы в `pubspec.lock`.

```sh
flutter pub get --enforce-lockfile
flutter run -d windows
# На Linux:
flutter run -d linux
# В браузере:
flutter run -d chrome
```

На экране входа нет поля сервера. `ServerIpProvider.load()` читает `GOVOR_SERVER` из параметров сборки, а без переопределения — из включённого в приложение `config/production.json`. Для обычного запуска дополнительные параметры не нужны.

```sh
flutter run -d windows --dart-define-from-file=config/desktop-local.json
flutter run -d android --dart-define-from-file=config/android-local.json
```

Локальные конфигурации используют localhost и адрес Android-эмулятора 10.0.2.2. HTTP разрешён только в debug при явном `GOVOR_ALLOW_LOCAL_HTTP=true` и только для поддерживаемых локальных адресов. Release принимает только HTTPS. Сейчас config/production.json содержит localhost для разработки; перед выпуском задайте фактический HTTPS-адрес сервера через этот файл или GOVOR_SERVER. Release с текущим HTTP-адресом не пройдёт проверку адреса при старте. JSON и dart-define — публичные настройки, секреты туда не помещаются.

Версия определяется из метаданных установленного пакета через `package_info_plus`. Источник по умолчанию — `version` в `pubspec.yaml`; сборка может переопределить его через `--build-name` и `--build-number`. В интерфейсе отдельной константы версии нет.

## Реализовано

- Вход и регистрация по SRP, восстановление архива ключей, смена пароля и явный сброс ключей.
- Личные разговоры, группы и каналы, история, поиск, ответы, редактирование, удаление, выбор и пересылка сообщений с медиа и серверными метаданными происхождения.
- Markdown в сообщениях и описаниях профилей; предпросмотр изображений и видео, галерея с масштабированием фото и сохранением файлов.
- Шифрование текста и файлов, повторная отправка с тем же ID при неопределённом подтверждении, черновики при переключении разговоров.
- Друзья, входящие и исходящие заявки, поиск пользователя по имени/ID; окно чужого профиля с действиями по текущему статусу дружбы.
- Профиль, аватар, автосохранение описания, сессии, паки реакций; управление группами, участниками и приглашениями с учётом роли.
- Стеклянные поверхности, исходные шрифты и пять обоев MAUI-клиента. Обычные изображения обоев отображаются отдельными непрозрачными миниатюрами.
- Пользовательские фоны PNG/JPEG/WebP: до 6 изображений, каждое до 5 МБ / 24 Мп. Они копируются в локальное хранилище приложения; исходный файл впоследствии не нужен. В web используется Cache Storage только для оформления. При ошибке записи выбранный фон сохраняется прежним.
- Деморежим для просмотра интерфейса без сервера; его сообщения существуют только в памяти.

## Интерфейс ПК

От 820 логических пикселей главное окно показывает навигацию, список разговоров и переписку одновременно. При уменьшении окна сохраняются выбранный разговор и черновик. Профиль использует две колонки от 904 px внешней ширины: компактные настройки слева и сетка фонов справа. Настройки оформления, защиты и паков открываются в правой области без новой страницы. На телефоне применяется одна колонка с горизонтальной каруселью, защита и паки открываются отдельной страницей.

Ctrl+Enter / Cmd+Enter отправляет сообщение, Enter оставляет возможность набрать многострочный текст. Правая кнопка мыши открывает действия с сообщением; меню выделенного текста предоставляет копирование и переход к действиям. Escape закрывает профиль. Элементы управления поддерживают фокус клавиатуры, подписи и подсказки.

## Хранение и протокол

Ключи и токены Android/Windows/Linux хранятся через платформенное защищённое хранилище. В браузере секреты существуют только в памяти страницы: после перезагрузки требуется вход и восстановление архива. Оформление хранится отдельно от секретов, локально для установки/браузера.

SRP использует параметры существующего сервера; серверное доказательство проверяется до сохранения сессии. E2EE реализует совместимый формат `govor.e2ee.v1`: ES256, RSA-OAEP-256 и A256GCM, сертификаты устройств, привязку к разговору/отправителю/ID/редактированию и проверку изменений идентичности. Приватные ключи записываются в архив до регистрации устройства. Новые сообщения при ошибке E2EE не переключаются в открытый текст. Исторические незашифрованные сообщения помечаются `[Без E2EE]`.

Refresh выполняется последовательно для параллельных запросов, оба токена сохраняются одной записью; временная сетевая ошибка не уничтожает ключи и сессию. HTTP-переадресации с авторизацией запрещены, содержимое ошибок сервера не выводится напрямую. Файлы шифруются до загрузки; имя и ключ находятся внутри E2EE-сообщения.

Это ещё не полный функциональный паритет с MAUI: звонки, push-уведомления, QR-сканер, аудиопроигрыватель и запись голосовых сообщений требуют дальнейшего переноса. Изображения и видео уже имеют inline-предпросмотр; неподдерживаемые кодеки/форматы можно сохранить. Старые аккаунты с legacy-аутентификацией сначала требуют миграции через исходный клиент. Списки групп и участников загружаются постранично до исчерпания. Живой обмен с production-аккаунтом отдельно от изолированных тестов не проверялся.

## Локализация и архитектура

Интерфейс использует типизированные ARB-ключи Flutter gen-l10n: русский, английский и системный язык. Размер основного текста настраивается ползунком 12–24 с предпросмотром и локальным сохранением. До входа язык определяется системой; в профиле доступен выбор языка с локальным сохранением. Пользовательский текст не переводится; часть диагностик старых сервисов пока остаётся русской.

Зависимости собираются через AppDependencies и передаются конструкторами. Настройки, оформление, автосохранение профиля, просмотр чужого профиля, выбор реакций и загрузка медиа используют отдельные Cubit (flutter_bloc). MessengerController остаётся MVVM-координатором сессии/переписки. Подробности: [архитектура](docs/architecture.md), [сверка API и оставшиеся возможности](docs/api-audit-2026-10-31.md).

Реализованы удаление друга, блокировка и снятие собственной блокировки. Govor+ и профильные теги отображаются по серверным benefits; доступны редактор тега и административная настройка привилегий. Внешние Markdown-изображения и GIF загружаются автоматически отдельным HTTP-клиентом без токенов API; такие запросы раскрывают хосту изображения IP читателя. Размер и формат проверяются. Подробнее: [изменения интерфейса и API](docs/messaging-ui-update-2026-10-31.md).

## Проверки

```sh
dart format --output=none --set-exit-if-changed lib test
flutter analyze
flutter test --coverage --reporter expanded
```

Тесты проверяют криптографическую совместимость с .NET, подмену контекста и повреждение шифротекста, гонки refresh/logout, конфликты архива и откат, смену идентичности, настоящий локальный WebSocket с SignalR handshake/reconnect. Проверки интерфейса охватывают отправку, поиск и сохранение черновика, изменение размеров окна, Ctrl+Enter, контекстное меню, автосохранение описания и пользовательские фоны.

`test/fixtures/dotnet.json` содержит исключительно опубликованные тестовые ключи. Обратная проверка использует существующую C#-реализацию протокола:

```sh
dotnet run --project tools/interop -- test/fixtures/dotnet.json
flutter test test/crypto_interop_test.dart
dotnet run --project tools/interop -- verify build/interop/dart.json
```

Для генератора нужен .NET 10 и соседний исходный репозиторий Govor; путь можно задать свойством `ServerRoot`. Обычный `flutter test` использует готовый fixture и не требует C#-репозитория. `coverage/lcov.info` содержит покрытие строк. `tools/media_smoke.dart <libmpv> <video>` проверяет нативный декодер и очистку временного источника. `test/preview_test.dart` создаёт PNG экранов в `build/previews` с реальными шрифтами и загруженными обоями.

## Сборки

```sh
flutter build windows --release --dart-define-from-file=config/production.json
flutter build linux --release --dart-define-from-file=config/production.json
flutter build web --release --no-web-resources-cdn --pwa-strategy=none --dart-define-from-file=config/production.json
flutter build apk --debug --dart-define-from-file=config/production.json
```

Windows собирается на Windows с компонентами Visual Studio «Desktop development with C++» и ATL. Распространяется вся папка `build/windows/x64/runner/Release`, а не только EXE.

Linux собирается на Linux. Для Ubuntu нужны clang, cmake, ninja-build, pkg-config, libgtk-3-dev и libsecret-1-dev; во время работы — доступный Secret Service (например GNOME Keyring) и файловый портал xdg-desktop-portal. Локальная Windows-сборка не подтверждает работу Linux: для него предусмотрено отдельное задание CI.

Web требует HTTPS (либо localhost для разработки), корректного CORS/WebSocket Origin на сервере. Сборка включает web-ресурсы Flutter локально. Необходимо раздавать всё содержимое `build/web`.

Android требует SDK, JDK 21 и принятых лицензий SDK, минимальная версия Android 7 / API 24. Debug APK предназначен для разработки. Для release скопируйте `android/key.properties.example` в локальный `android/key.properties` и укажите собственное закрытое хранилище подписи. Пароли и keystore исключены из контроля версий; release без них завершается ошибкой, debug-ключ в release не подставляется.

В `../.github/workflows/flutter.yml` подготовлены проверки и независимые сборки Windows, Linux, web и Android debug. Workflow начнёт выполняться после размещения репозитория в GitHub; его наличие само по себе не означает, что удалённые сборки уже прошли.

## Обновления Android из GitHub Releases

Клиент проверяет публичные релизы Govor-team/Govor.DartClient при открытии, каждые 4 часа и при возвращении в приложение (не чаще раза в 15 минут). Репозиторий можно изменить через --dart-define=GOVOR_UPDATE_REPOSITORY=owner/repo. Токен в приложение не встраивается.

Публикуйте стабильный релиз с тегом v1.2.3 или v1.2.3+45 и подписанным APK: app-release.apk (универсальный) либо app-arm64-v8a-release.apk, app-armeabi-v7a-release.apk, app-x86_64-release.apk. GitHub должен вернуть SHA-256 digest файла. Debug, prerelease и draft пропускаются. Для каждой новой Android-сборки увеличивайте --build-number и сохраняйте прежний applicationId и ключ подписи. Версия тега должна совпадать с --build-name (а суффикс +N, если есть, с --build-number).

Кнопка загружает APK в закрытый кэш, проверяет размер, SHA-256, packageName и увеличение versionCode, затем открывает системный установщик. Android проверяет подпись и запрашивает подтверждение. При первом обновлении разрешите установку из этого источника и нажмите кнопку повторно. Этот путь предназначен для APK, распространяемых через GitHub; для iOS и web плашка отключена. Публикация релиза и подпись остаются отдельным шагом выпуска.

## Оформление

В широком окне перетаскивайте зазор между списком чатов и перепиской. Минимальная ширина списка — 92 логических пикселя: остаются аватарки, подсказки, индикаторы непрочитанного и переключение друзей/групп. Зазор сохраняется 12 пикселей. Ширина сохраняется локально и ограничивается размером окна.

Настройки → Оформление → Стеклянный эффект меняет размытие и непрозрачность всех Glass-панелей, включая окна и вложенные элементы. Значение применяется сразу и сохраняется при отпускании ползунка. В режиме высокой контрастности сохраняются непрозрачные панели.
